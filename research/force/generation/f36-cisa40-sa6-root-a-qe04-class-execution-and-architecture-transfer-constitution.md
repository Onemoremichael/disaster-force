# RBF-1 — Root A QE-04 class execution and architecture-transfer constitution

## Decision abstract

`RBF-1` defines the complete twelve-cell `AM-05 QE-04` class after one accepted 500-kilogram seed event under [RBE-1](f36-cisa40-sa6-root-a-first-qe04-architecture-and-am05-event-constitution.md). Its subject is not eleven repetitions. It is the transfer of one selected source-system architecture across six public rigs, two primary truth roots, two unlike builder lineages, three campuses, twelve root-dedicated source-contact modules and every source-exposed return.[1–7]

The central finding is that a 672-hour return rule can attach to the wrong physical object. If the entire host rig remains unavailable for twenty-eight days, six rigs support only 1.5 starts per week. If each exact rig–root cell receives its own independently serialized route, stop-energy element, receiver, capture liner and source-contact boundary, the host can alternate unlike root modules every 336 hours while each source-exposed module still completes the full 672-hour return. That topology supports three starts per week. The faster result is lawful only after a separate seventy-two-trial exchange campaign proves installation, isolation, datum recovery, cross-talk control, safe rollback and evidence continuity in both ordered directions on every rig.

RBF-1 therefore carries two complete calendars. Under `MEX-QUALIFIED`, twelve module-return lanes, six hosts, three campus event units, three package-preparation paths and three evidence paths balance at three starts per week. After the exchange decision, the eleven remaining primary events finish by day 21, their returns by day 49 and class review by day 63. All sixteen reserves distributed across the pool finish class review by day 98. Eight reserves concentrated in one cell place review at day 266. Both eight-reserve family queues concentrated in the two cells of one non-seed rig require eighteen alternating events and place review at day 280.

Under `MEX-DENIED`, the program receives no 336-hour host-reuse credit. The same eighteen-event local sequence uses twenty-eight-day intervals; its last event occurs on day 476, return on day 504 and review on day 518. The seventy-two-trial exchange campaign occupies twelve planning weeks before either source calendar. Total planning boundaries from exchange-campaign start are therefore 147 days for primary execution, 182 days for distributed maximum execution, 364 days for the binding qualified-exchange concentration and 602 days for the denied-exchange fallback. The twenty-four-month stage carries the fallback without pretending the exchange innovation has already worked.

The class source bank remains the thirty 600-kilogram packages constituted in RBE-1: twelve active, sixteen operational reserves divided eight per truth-root family, and two untokened forensic references. Gross custody is 18,000 kilograms. Required event issue is 6,000 kilograms; maximum issue across twenty-eight attempts is 14,000 kilograms. Reserves replace only independently invalid attempts in the same exact cell and truth-root family. A valid adverse event remains in the class and denies that cell.

Source-package reserve and module reserve are different systems. RBF-1 creates eighteen selected-architecture source-contact modules: twelve active root-dedicated modules, four dormant operational spares divided by builder lineage and two sealed forensic references. A module spare cannot become an extra attempt token. It can enter only after a same-lineage `EXCHANGE-REBASE` decision reconstructs geometry, calibration, safeing, receiver capacity, source-contact history and outside-origin evidence. The four spares are resilience against isolated hardware loss, not a promise to survive common-cause architecture failure.

Builder lineage is crossed with primary truth root rather than confounded with it. On rigs 1, 3 and 5, `TR-A` receives builder lineage `BL-A` and `TR-B` receives `BL-B`; rigs 2, 4 and 6 reverse the assignment. Every campus therefore contains all four truth-root–builder-lineage combinations. Both truth roots observe every attempt. One owns the exact cell decision prospectively. The class reports rig, campus, truth-root, builder-lineage and exchange-direction contrasts separately.

Each attempt remains the complete RBE-1 event: forty-eight event gates, 236 dossier objects, thirty-six safeing paths, seventy-two root-specific measurements, twelve samples, twenty return work packages, eighteen return decisions and twenty-four outside-origin replay decisions. Required execution therefore creates 576 event-gate instances and 2,832 dossier bindings; maximum capacity creates 1,344 and 6,608. Every invalid packet, hardware transition and public intervention remains visible.

The class receives fixed twelve-credit source budgets rather than twenty-eight attempt allowances. Environmental source may not exceed 6.000 kilograms and unaccounted source may not exceed 45.000 kilograms across every issued attempt. Each credit must independently meet ancestry recovery of at least 0.995, cross-talk no more than 0.005, capture area no more than 6.25 square metres, measured peak pressure no more than 1.8 megapascals, the 2-megapascal structural boundary, measured receiver availability and the 5-kilogram expanded-uncertainty ceiling. A clean replacement cannot erase earlier loss.

Evidence provision rises from approximately 4,578.333 gigabytes native and 5,951.832 gigabytes allocated for the twelve-credit class to approximately 10,682.776 gigabytes native and 13,887.609 gigabytes allocated for all twenty-eight possible attempts. Eighteen terabytes of governed class capacity preserves indexes, manifests, repair copies and investigation space alongside the required originals. Physical samples, source lots, wetted modules and waste remain physical evidence.

RBF-1 cannot fit inside the exhausted `RAS-1` child authority. It therefore proposes `RAS-2R`, a transparent baseline amendment rather than an unfunded mandate. The class requires USD 180 million incremental capital, USD 28 million per year and USD 160 million of cross-classified technology. Twenty-four-month stage exposure is USD 236 million. Revised parent boundaries become USD 800 million capital, USD 263 million per year and USD 1.165 billion technology. At the inherited thirty-month parent basis, gross parent exposure is USD 1.4575 billion. Cumulative child-stage exposure becomes USD 1.17425 billion, leaving USD 283.25 million between child-stage exposure and the revised gross parent boundary.

The 560-position formation contains three complete campus event units, twelve module-return lanes, an independent exchange and rebaseline function, three package-preparation paths, evidence and outside replay, environmental and waste custody, and separated safety, validity, source and portfolio authorities. It is a permanent public test formation, not a contractor surge cell.

The companion model contains twenty-five sheets. It preserves every physical observation and class-decision field as open. Seventy-two exchange trials, eighteen module records, twelve exact cells, thirty packages, twenty-eight attempt positions, twenty-eight return cycles, twenty-two host transitions, six unlike-root contrasts, 120 executable boundary cases and 240 planning audits make the topology, calendars, source limits, evidence and finance testable. Planning completion does not assert that RBE-1 closed, an exchange occurred, a second 500-kilogram event issued or the selected architecture transferred.

An accepted RBF-1 class grants bounded `AM-05 QE-04` architecture transfer. If `MEX-QUALIFIED` also closes, it grants the narrower modular-exchange claim. It authorizes only constitution of `RBG-1`, a reset of the `AM-06` source, ignition and water-entry ladder. It does not issue an `AM-06` event, admit a drainage candidate, authorize fire, production, fleet procurement, export release or exterior rendering.

## 1. The object of transfer

The governing proposition is:

> Can one selected 500-kilogram unignited-source architecture transfer across twelve prospectively assigned rig–truth-root cells while builder lineage, source family, source-contact module, receiver, host exchange, return, evidence and fixed class source accounts remain identifiable under invalidity and concentrated loss?

The proposition has three nested claims.

1. **Event transfer:** each exact cell can execute the accepted RBE-1 event.
2. **Architecture transfer:** the selected architecture remains decidable across rigs, campuses, truth roots and builder lineages.
3. **Module-exchange transfer:** a host may alternate two source-contact modules without borrowing state, contamination or evidence between them.

The first two are required for the class. The third is optional but valuable. Failing module exchange does not make an unsafe event acceptable. It removes only the 336-hour host-reuse claim and forces the slower calendar. Failing event or architecture transfer denies the class.

## 2. Five identities that cannot be merged

RBF-1 preserves five populations.

- A **cell** is one exact rig, primary truth root, selected architecture and builder-lineage proposition.
- A **module** is one serialized source-contact system containing route, stop-energy element, receiver, capture liner, local safeing interface and physical-state witnesses.
- An **attempt** is one issued 500-kilogram event with a package, module, incoming baseline, causal clock, terminal ledger and native packet.
- A **credit** is the one valid result that can close an exact cell.
- A **return cycle** joins the module's incoming state, attempt, delayed observations, work, rebaseline and release.

Every issued attempt enters the validity, source and return denominators. Every source-exposed module enters the return denominator. A valid contained event can create one credit only after return closes. A valid adverse event earns no passing credit and cannot receive a replacement. `INVALID` means that the registered proposition did not occur or cannot be interpreted because a declared prerequisite failed. Only invalidity can activate the next source package.

A hardware spare is not a source reserve. A source reserve is not a class credit. A clean receiver is not an accepted module. These distinctions prevent the program from solving one shortage by relabeling a different inventory.

## 3. Selected-architecture freeze

RBF-1 accepts one architecture identity, `AS-1`, from the RBE-1 architecture board and accepted seed packet. If RBE-1 admitted multiple architectures, the architecture used for the accepted seed becomes the class architecture unless a prospective amendment repeats the first-event proof on another baseline. Parts from two admitted architectures cannot be combined into a convenient hybrid during the class.

The freeze includes:

- route number, bore, length and internal geometry;
- normal schedule and target waveform;
- stop-energy topology and settings;
- final control elements, passive last states and casualty diversion;
- receiver geometry, usable-volume method and gas-space state;
- capture-plane interface and source-contact materials;
- pressure, mass, volume, position, time and ancestry measurement roots;
- control code, safety code and independently replayable transforms;
- robotic inspection and recovery interfaces;
- replaceable-boundary definition and forbidden substitutions; and
- the complete qualification and first-event evidence references.

The class may update serials, calibration coefficients and accepted consumables through declared processes. It cannot change the architecture-defining variables and still call the event the same proposition.

## 6. Seventy-two ordered module-exchange trials

Module exchange is a physical claim. Each rig executes both ordered directions, `TR-A` module to `TR-B` module and `TR-B` module to `TR-A` module, under six challenge families. Six rigs by two directions by six challenges create seventy-two required valid trials.

| Trial family | Challenge | Required truth |
|---|---|---|
| `MX-1` | nominal removal and installation | geometry, seals, safeing, receiver and evidence restore |
| `MX-2` | datum offset at accepted edge | independent coordinate recovery without hidden fit |
| `MX-3` | one connector or service denied | passive safe state and explicit unavailable function |
| `MX-4` | campus network and primary time removed | local identity, order and two complete originals |
| `MX-5` | blinded residual marker in outgoing boundary | no cross-cell borrowing; ancestry and location recover |
| `MX-6` | interrupted installation and emergency rollback | safe isolation, casualty path and reconstructable final state |

Each trial begins with a known clean or seeded nonenergetic module, not an empty administrative record. The outgoing module receives a terminal inventory and custody seal. The host receives an interface survey. The incoming module receives independent geometry, leak, capacity, safeing, calibration and evidence checks. The exchange result is not the sum of two module certificates; it is the observed transition between them.

`MEX-QUALIFIED` requires all seventy-two valid trials, zero valid adverse safeing or cross-talk results, both direction decisions on all six rigs, three campus decisions and one national exchange decision. Invalid trials remain in the denominator and can be repeated only under the registered reserve rule for nonenergetic trials. A missing direction denies host-reuse credit on that rig.

## 7. Two lawful host-use states

### 7.1 Qualified exchange

Under `MEX-QUALIFIED`, the source-contact module remains unavailable for at least 672 hours after its event. The host rig may accept the other root-dedicated module no earlier than 336 hours after the prior event, after outgoing isolation and incoming acceptance. The two clocks are independent:

\[
t_{same\ module}\ge672\;h,\qquad t_{same\ host,unlike\ module}\ge336\;h.
\]

The 336-hour value is not half-cleanliness. It is a host inspection, interface-restoration and crew-recovery boundary. Source-contact return remains twenty-eight days.

### 7.2 Denied exchange

Under `MEX-DENIED`, no alternate module can receive source on that host before 672 hours. The class can continue only through a fixed-boundary path if the architecture, receiver and event gates remain accepted. This path can establish that the event transfers across fixed cells. It cannot establish rapid modular exchange.

The decision is rig-specific during execution and national at class review. A mixed result may force some rigs to 672-hour host intervals. RBF-1 carries the all-qualified and all-denied outer calendars; the actual compiler schedules each rig from its observed exchange state.

## 10. Reserve concentration calendars

### 10.1 Distributed maximum

After the accepted seed, twenty-seven possible attempts remain: eleven primaries and sixteen reserves. At three starts per week, nine weekly issue positions place the last event on day 56, return on day 84 and review on day 98. Including exchange qualification, the planning boundary is day 182.

### 10.3 Both families concentrated on one non-seed rig

The maximum authorized qualified-exchange concentration assigns all eight `TR-A` reserves to one cell and all eight `TR-B` reserves to the other cell on the same non-seed rig. The host executes eighteen attempts, alternating modules every fourteen days. Events run from day 0 through day 238. The final module returns on day 266 and class review occurs on day 280. The class uses twenty-eight attempts in total, but only twenty-seven occur after `C0`; over the forty post-`C0` weeks through review, average national issue rate is 0.675 per week, or 22.5 percent of installed three-per-week capacity. Exact-host concentration, not aggregate equipment, governs.

### 10.4 Denied-exchange fallback

Without host exchange, the same eighteen-event local sequence uses twenty-eight-day host intervals. Events run from day 0 through day 476. Final return occurs on day 504 and class review on day 518. Including the exchange campaign that produced the denial, the planning boundary is day 602.

The twenty-four-month stage leaves approximately 128 days beyond this constructed fallback. It does not guarantee recovery from common-cause architecture failure, campus loss or an exhausted module-spare bank. Those conditions stop or amend the class.

## 22. Research stocktake

RBF-1 adds seven conclusions to the Department design.

First, return time belongs to a physical state, not automatically to the largest visible machine. Assigning the clock to the source-contact module can increase host availability without relaxing source recovery.

Second, modularity is a transition claim. A removable object is not operationally exchangeable until both ordered directions, degraded installation, residual custody, rollback and outside reproduction pass.

Third, multiple reserve systems must remain separate. Source packages, wet modules, host rigs, evidence paths and trained crews fail differently. Treating one as spare capacity for another creates fictional readiness.

Fourth, experimental balance requires orthogonal industrial assignment. Crossing builder lineage with truth root at every campus prevents an industrial defect from masquerading as a measurement disagreement.

Fifth, the maximum calendar is again topological. Three starts per week closes the distributed class rapidly, but eighteen identity-constrained attempts on one host still govern the authorized concentration.

Sixth, innovation should retain a lawful fallback. The class can proceed slowly after an exchange denial without crediting the failed capability. That is more ambitious than avoiding the technology and more honest than assuming it works.

Seventh, fiscal exhaustion is evidence. The existing parent can define and seed the architecture but cannot execute the complete transfer class. A serious Department must reopen the baseline when the physical service cycle requires more modules, return cells, public laboratories and people.

The next admissible object after an accepted class is `RBG-1`, the `AM-06` source, ignition and water-entry ladder reset. It must decide whether the energetic method begins with a new zero-source/water datum, 100-kilogram entry, an intermediate source state or another bounded progression. It must create separate source and water modules, ancestry roots, intervention rules, casualty destinations and thermal authority before any fire event. Drainage-candidate entry, production, fleet procurement, export release and exterior rendering remain blocked.
